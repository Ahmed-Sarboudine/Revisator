Descente de gradient

Polynôme convexe, nombre d'or, gradient à pas fixe,
critères d'arrêt, cas multi-variable, pas optimal

À retenir en priorité
  • Mise à jour : xt+1 = xt − μ · ∇f(xt) — on va à l'opposé du gradient (le gradient pointe vers la montée). μ = pas (hyperparamètre, choisi à la main).
  • Recalculer le gradient au nouveau point à chaque itération.
  • Pas trop petit → convergence très lente. Pas trop grand → oscillations, puis divergence. Ici (f = 2x² − 4x + 5) : converge ⇔ 0 < μ < 0,5.
  • Critères d'arrêt : ‖∇f(x)‖ ≤ ε (convergence) · nombre max d'itérations · f ne diminue plus (divergence détectée).
  • Multi-variable : f(x) = xTAx + xTb + c ⇒ ∇f = (A + AT)x + b (pas 2Ax si A n'est pas symétrique).
  • Pas optimal : à chaque itération, μk = argmin g(μ) = f(xk − μ∇f(xk)), trouvé par la méthode du nombre d'or → 12 itérations au lieu de 144.
  • Convexe ⇒ un seul minimum : x0 ne change que le nombre d'itérations. Non convexe ⇒ risque de minimum local, résultat dépendant de x0.

1. Le problème : trouver un minimum

Au cours 1, apprendre un modèle = trouver μ* = argminμ g(fμ,λ, {X, Y}). En général pas de formule fermée, fonction parfois non convexe, beaucoup de paramètres → il faut une méthode itérative : c'est l'objet du TD.

Polynôme d'ordre 2 : f(x) = ax² + bx + c

  • Convexe ⇔ f''(x) = 2a > 0 ⇔ a > 0 (b et c quelconques).
  • Minimum où f'(x) = 2ax + b = 0 ⇒ xopt = −b / (2a).
Le polynôme du TD : a = 2, b = −4, c = 5
f(x) = 2x² − 4x + 5 · f'(x) = 4x − 4 (compute_df)
xopt = 4 / 4 = 1 · f(1) = 2 − 4 + 5 = 3 (et non c = 5)
Piège de notationDans le cours, μ désigne les paramètres du modèle (ce qu'on cherche). Dans le TD, μ est le pas de la descente (souvent noté η ou « learning rate » ailleurs). Le pas est un hyperparamètre : il n'est pas appris.

2. Méthode du nombre d'or (fonction à une variable)

Conditions : f mono-variable et unimodale sur un intervalle (x1, x3) qui contient le minimum. Aucune dérivée, aucun pas : seulement des valeurs de f.

Sondes (φ = (1 + √5)/2 ≈ 1,618 ; 1/φ ≈ 0,618) :

x2 = x3 − (x3 − x1)/φ  ·  x4 = x1 + (x3 − x1)/φ

  • Si f(x2) < f(x4) : minimum dans (x1, x4) → x_3 = x_4.
  • Sinon : minimum dans (x2, x3) → x_1 = x_2.
  • Arrêt quand |x2 − x4| ≤ ε ; on renvoie (x1 + x3)/2.
  • L'intervalle est multiplié par 0,618 à chaque itération (comme une dichotomie, mais avec φ au lieu de 2).
Exemple du TD : intervalle (−100 ; 100) 
(x3 − x1)/φ = 200 / 1,618 ≈ 123,6
x2 = 100 − 123,6  = −23,6   f(x2) ≈ 1214
x4 = −100 + 123,6 = +23,6   f(x4) ≈ 1025
f(x2) > f(x4)  →  x1 = x2
nouvel intervalle : (−23,6 ; 100)
nouvelles sondes  : 23,6 et 52,8

Sortie de la correction (ε = 10−10) : x_opt = 1.0000000104692428.

3. Algorithme du gradient

Il ne demande qu'un point de départ x0 (et un pas) et marche en dimension quelconque. Le nombre d'itérations n'est pas connu d'avance.

Méthode : faire un pas de descente de gradient à la main
  1. Dériver f (ou calculer le vecteur gradient en multi-variable).
  2. Évaluer le gradient au point courant xt.
  3. Multiplier par le pas μ.
  4. Soustraire : xt+1 = xt − μ · f'(xt). Gradient négatif ⇒ x augmente.
  5. Contrôler : f(xt+1) < f(xt) ? Sinon le pas est trop grand (ou il y a une erreur de signe).
  6. Pour le pas suivant, recalculer le gradient en xt+1.
1D : f = 2x² − 4x + 5, x0 = 10, μ = 0,1 
f'(10)  = 4×10 − 4   = 36
x1 = 10  − 0,1×36    = 6,4    f: 165 → 61,32
f'(6,4) = 4×6,4 − 4  = 21,6
x2 = 6,4 − 0,1×21,6  = 4,24   f: → 23,995
2D : f du TD, x0 = (−5, −5), μ = 0,05 
A + Aᵀ = [4 3 ; 3 8]
∇f(x0) = (−35, −55) + (1, 2) = (−34, −53)
x1 = (−5, −5) − 0,05×(−34, −53)
   = (−5 + 1,7 ; −5 + 2,65)
   = (−3,3 ; −2,35)       f: 212 → 61,135
Erreurs typiques sur un pas
  • Signe + : 10 + 3,6 = 13,6 → on monte.
  • Réutiliser l'ancien gradient : 6,4 − 0,1×36 = 2,8 au lieu de 4,24.
  • Utiliser f au lieu de f' : 10 − 0,1×165 = −6,5.
  • En 2D : prendre 2Ax + b (→ (−29, −58)) ou oublier b (→ (−35, −55)).

4. Influence du pas μ (pas fixe)

Pour f = 2x² − 4x + 5 : xt+1 − 1 = (1 − 4μ)(xt − 1). La distance au minimum est multipliée par 1 − 4μ à chaque pas ⇒ convergence ⇔ |1 − 4μ| < 1 ⇔ 0 < μ < 0,5. Départ x0 = 10 (cellule de la correction) :

Pièges sur le pas (learning rate)
  • Plus grand n'est pas plus rapide : μ = 0,1 et μ = 0,4 demandent toutes deux 42 itérations ; au-delà de 0,5 plus rien ne converge.
  • Osciller ≠ diverger : μ = 0,4 oscille mais converge ; μ = 0,5 oscille sans converger ; μ = 0,6 diverge.
  • Trop petit ne « casse » rien mais coûte énormément d'itérations (et peut buter sur max_iter).
  • La plage de bons pas dépend de la fonction (de sa courbure), pas du point de départ. En 2D (essais hors TD, x0 = (−5, −5)) : μ = 0,05 → 144 itérations, 0,1 → 70, 0,2 → 244, 0,21 → divergence dès le 1er pas.

5. Critères d'arrêt et lecture du code

def algo_gradient3(f, df, mu, x_0, epsilon, max_iter):
    x = x_0; x_hist = [x]
    fx = f(x); dfx = df(x); k = 0
    while(np.linalg.norm(dfx) > epsilon
          and k < max_iter):
        x = x - mu*dfx           # pas de descente
        x_hist.append(x)
        if(f(x) >= fx):          # f ne baisse plus
            break                # → divergence
        fx = f(x); dfx = df(x)   # gradient recalculé
        k = k + 1
    return x, x_hist

Lire les sortiesAvec μ = 0,05, la correction affiche compute_df2(x_opt_2) = [-4.6e-08 2.5e-08] : la norme est au-dessus de ε = 10−10 et seules 144 itérations ont tourné. C'est donc le test f(x) ≥ fx qui a arrêté la boucle : f ne baisse plus à la précision machine près. Ce n'est pas une divergence, x est bien à l'optimum (−0,087 ; −0,217).

6. Cas multi-variable

Même règle, en vecteurs : xk+1 = xk − μ · ∇f(xk)

f(x) = xTAx + xTb + c, avec A = [2 1 ; 2 4] (non symétrique), b = (1, 2), c = 2.

  • ∇f(x) = (A + AT)x + b, avec A + AT = [4 3 ; 3 8].
  • Minimum : ∇f = 0 ⇔ (A + AT)x = −b ⇒ xopt = −(1/23)(2, 5) ≈ (−0,087 ; −0,217), f(xopt) = 40/23 ≈ 1,739.
  • x doit être un vecteur numpy 1D de forme (2,) : np.array((-5., -5.)), np.zeros(2). Pas np.zeros((2,1)) (le gradient devient une matrice 2×2), pas une liste (pas de .T).
Valeurs en x0 = (−5, −5) 
xᵀAx = 25×(2+1+2+4) = 225
xᵀb  = −5 − 10      = −15
f(x0) = 225 − 15 + 2 = 212
∇f(x0) = (−34, −53)
Erreurs : 242 (signe de xTb), 210 (oubli de c), 137 (diagonale seule).

7. Pas optimal

Le pas fixe demande beaucoup d'itérations et un bon μ est difficile à trouver. Idée : une fois la direction −∇f(xk) connue, chercher jusqu'où descendre :

μk = argminμ>0 g(μ),   g(μ) = f(xk − μ · ∇f(xk))

ft = lambda mu : f(x - mu*dfx)   # g(μ), mono-variable
mu_opt = mno(ft, 0, 100, 1e-10)  # nombre d'or
x = x - mu_opt*dfx
