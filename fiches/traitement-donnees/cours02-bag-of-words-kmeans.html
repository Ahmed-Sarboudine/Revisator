Sac de mots, TF-IDF et K-Means

Notebooks « Bag of words » et « K-Means » :
représenter des textes, puis les regrouper

À retenir en priorité
  • Non supervisé : on ne connaît ni les classes ni leur nombre ; on regroupe par ressemblance (clustering).
  • Sac-de-mots = histogramme des occurrences des mots du dictionnaire (vecteur de la taille du vocabulaire, creux). Ni ordre, ni syntaxe.
  • Vocabulaire appris sur le train (fit), test seulement transform : un mot hors vocabulaire est ignoré.
  • TF = n(t,doc) / Card(doc) · IDF = log(M / nb de docs contenant t) : 0 si t est partout, log M s'il est dans un seul doc.
  • Plus gros gain : la suppression des stop words (precision@1 0,49 → 0,75). BM25 > TF-IDF ici (longueurs très variables).
  • K-Means minimise J = ∑k ∑i∈Ck ‖xi − μk‖² : affecter au centre le plus proche, puis centre = barycentre, jusqu'à stabilité.
  • Minimum local → plusieurs initialisations (n_init, k-means++). J décroît toujours avec K → choisir K par le coude ou la silhouette.
  • K-Means suppose des variables à la même échelle (StandardScaler) et des groupes convexes (échec sur cercles concentriques).

1. Du texte au vecteur : one-hot et sac-de-mots

Donnée catégorielle à K valeurs → vecteur one-hot « 1 parmi K » plutôt qu'un entier 1…K :

  • toutes les catégories sont à la même distance (pas d'ordre artificiel) ;
  • la moyenne de ces vecteurs donne la proportion de chaque catégorie.

Sac-de-mots (extension du one-hot) : composante i = nombre d'occurrences du i-ème mot du dictionnaire dans le document.

Jeu de données : articles du Monde (MLSUM), 6 rubriques × 2 000 articles → train 9 600, test 2 400 (1 600 par catégorie dans le train).

Vecteurs creux : très grands (≈ 107 000 mots bruts), presque tous nuls → problème de mémoire (géré par scipy.sparse) et de dimension (il faudrait beaucoup de données, sinon sur-apprentissage).

CountVectorizer passe déjà tout en minuscules par défaut.

Méthode : vecteur de comptage d'une phrase
  1. Tokeniser, minuscules, retirer les stop words.
  2. Pour chaque mot du vocabulaire appris sur le train (ordre des colonnes), compter ses occurrences.
  3. Les mots absents du vocabulaire sont ignorés (aucune colonne ajoutée).
Exemple : vocabulaire (chat, chien, mange, souris) · « Le chat mange la souris, puis le chat dort. »
→ chat 2, chien 0, mange 1, souris 1 : (2, 0, 1, 1) — « puis » et « dort » sont hors vocabulaire.

Mots hors vocabulaire (OOV) : ≈ 20 % du vocabulaire du test n'existe pas dans celui du train — surtout des noms propres.

Parade : méthodologique, en amont → un train le plus large et représentatif possible. Jamais apprendre le vocabulaire sur le test.

3. Évaluer une représentation (sans classifieur supervisé)

precision@k : pour chaque article du test, ses k plus proches voisins dans le train (similarité cosinus) ; part de voisins de même catégorie, moyennée sur le test. Baseline aléatoire : 1/6 ≈ 0,167.

t-SNE : projection 2D qui préserve les voisinages, après SVD tronquée. Outil de visualisation, pas de clustering : il ne crée pas de groupes.

Sous-ensemble Difficile = International, Société, Politique : fort recouvrement lexical. Facile = Sport, Culture, Économie.

precision@k : voisins Sport, Sport, Culture, Sport, Politique d'un article Sport → p@1 = 1, p@5 = 3/5 = 0,6.
Cosinus vs euclidienne cos(u, v) = u·v / (‖u‖ ‖v‖)
a = (2,0,1,1), b = (1,0,0,1), c = 2a = (4,0,2,2)
a·b = 3, ‖a‖ = √6, ‖b‖ = √2 → cos(a,b) = 3/√12 ≈ 0,87
d(a,c) = ‖(2,0,1,1)‖ = √6 ≈ 2,45 mais cos(a,c) = 1

Le cosinus ignore la longueur du document : même contenu doublé = similarité 1.

5. Pondération TF-IDF

TF : f(t, doc) = n(t, doc) / Card(doc)   IDF(t) = log( M / Card{doc : t ∈ doc} )   TF-IDF = f(t, doc) × IDF(t)

  • TF : normalise par la longueur → même comptage, document plus long = poids plus faible.
  • IDF : compte les documents (pas les occurrences). Terme partout → IDF = log 1 = 0 ; dans un seul doc → log M. IDF élevé = terme rare, discriminant.
Méthode : calculer un TF-IDF à la main (log népérien)

Corpus M = 4 : d1 = « but match but équipe », d2 = « match équipe joueur », d3 = « vote match loi », d4 = « vote loi match député ».

terme    docs  IDF = ln(4/docs)   TF-IDF
but       1    ln 4   = 1,386     d1 : 2/4 x 1,386 = 0,693
match     4    ln 1   = 0         0 partout
équipe    2    ln 2   = 0,693     d1 : 1/4 x 0,693 = 0,173   d2 : 1/3 x 0,693 = 0,231
vote      2    ln 2   = 0,693     d3 : 1/3 x 0,693 = 0,231   d4 : 1/4 x 0,693 = 0,173

Erreurs classiques : oublier de diviser par la longueur (but : 2,77), utiliser log10 (0,30), compter les occurrences dans l'IDF.

À savoirTfidfVectorizer de scikit-learn utilise en réalité une variante (IDF lissé ln((1+M)/(1+df)) + 1, comptages bruts puis normalisation L2 du vecteur) : c'est elle qui donne l'IDF max 8,38 = ln(9601/6) + 1. Pour un calcul à la main, prendre la formule du cours. Attribut des IDF appris : vectorizer.idf_.

6. BM25 : une pondération alternative

BM25(t,d) = IDFBM25(t) · tf·(k1+1) / ( tf + k1·(1 − b + b·|d| / avgdl) ) IDFBM25 = log(1 + (N − df + 0,5)/(df + 0,5))

  • Saturation de la fréquence : passer de 1 à 2 occurrences compte plus que de 10 à 11 (TF-IDF est linéaire).
  • Normalisation explicite par la longueur |d| / avgdl (longueur moyenne du train).
  • Hyperparamètres : k1 (saturation, 1,2–2,0) et b (poids de la longueur, ≈ 0,75). Référence d'Elasticsearch / Lucene.
  • Pas de BM25Vectorizer dans scikit-learn : le cours écrit un BM25Transformer branché après un CountVectorizer dans un Pipeline, même prétraitement que TF-IDF (alternative, pas cumul).
  • Gagne ici car les articles ont des longueurs très variables (300 à 45 000 caractères) ; sur des titres courts, aucun avantage → toujours mesurer.

7. L'algorithme des K-Moyennes (K-Means)

Points de référence : on affecte chaque point à la référence la plus proche. Frontière entre deux références = droite équidistante (médiatrice) ; pour toutes les paires → diagramme de Voronoï.

Critère (somme des inerties) :
J = ∑k=1..K ∑i∈Ck ‖xi − μk‖²
Inertie d'un groupe faible = groupe compact.

Paramètres appris : les centres μk et l'assignation des points. Hyperparamètres : K, n_init.

Algorithme
  1. Initialisation : K observations tirées au hasard parmi les données (scikit-learn : k-means++, centres initiaux éloignés).
  2. Assignation : chaque point → centre le plus proche (Voronoï des centres).
  3. Mise à jour : μk = moyenne des points du groupe.
  4. Recommencer 2–3 jusqu'à ce que les centres ou J ne bougent plus significativement (seuil relatif).

Pourquoi la moyenne ? Groupes fixés : ∇μkJk = −2 ∑i∈Ck(xi − μk) = 0 ⇒ μk = (1/nk) ∑ xi.

Minimum localJ décroît à chaque itération, mais vers un minimum qui peut être local selon les centres initiaux. On relance plusieurs fois (n_init, dizaines à centaines) et on garde le J final minimal. n_init ≠ nombre d'itérations (max_iter).

8. Choisir K et évaluer un clustering

J(K) décroît toujours avec K (J = 0 si K = nombre de points) : on ne minimise pas J pour choisir K.

Méthode du coude : Δrel(K) = (J(K−1) − J(K)) / J(K−1)
Le coude = dernier K qui apporte une forte baisse ; au-delà, gain marginal.

J(1..5) = 1000, 600, 150, 130, 120 → Δrel = 0,40 ; 0,75 ; 0,13 ; 0,08 → coude à K = 3.

Validation : ajuster les centres sur le train, comparer l'inertie moyenne par point sur train et validation (-clust.score(X)/len(X)) : courbes superposées = vraie structure, pas un hasard d'échantillonnage.

Silhouette (sans vérité terrain) :
s(i) = (b(i) − a(i)) / max(a(i), b(i))

  • a(i) : distance moyenne aux autres points de son cluster ;
  • b(i) : distance moyenne aux points du cluster voisin le plus proche (pas à son centre) ;
  • ≈ 1 bien placé, ≈ 0 frontière, < 0 mal affecté. Score global = moyenne. Non défini pour K = 1.
  • K trop grand (cluster coupé en deux) → silhouette baisse.
a = 0,8, b = 2,0 → s = 1,2/2 = 0,6 · a = 1,5, b = 1,0 → s = −0,5/1,5 = −0,33

ARI (avec vérité terrain) : 1 = partitions identiques à une renumérotation près, 0 = hasard. Seulement sur données synthétiques/étiquetées ; sur données réelles, la silhouette est la référence.

9. Limites de K-Means

Hypothèse impliciteQuand elle casseRemède
Variables comparables (distance euclidienne)Une variable ×30 sans information domine la distance : K-Means coupe selon elle (ARI ≈ 0)StandardScaler (moyenne 0, écart-type 1) → ARI ≈ 1
Groupes à peu près convexesCercles concentriques (make_circles) : ARI ≈ 0, même avec un grand n_initVariable x² + y² (idée du kernel trick) ou clustering spectral (graphe de plus proches voisins)

Autres familles évoquées : DBSCAN (densité), mélanges de gaussiennes, SVM à noyau (classification).
