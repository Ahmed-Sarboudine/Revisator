Couche application

HTTP, DNS, DHCP, SMTP / POP3 / IMAP,
FTP, Telnet et SSH

À retenir en priorité
  • La couche Application de TCP/IP = couches 5, 6 et 7 d'OSI.
  • HTTP : requête (MÉTHODE URL VERSION) → réponse (VERSION CODE TEXTE). GET lit, POST crée, PUT modifie. 200 OK, 400 Bad Request, 404 Not Found.
  • DNS : nom → IP. A (IPv4), AAAA (IPv6), PTR (inverse), NS, CNAME (alias), MX (mail), SOA.
  • DHCP (UDP 67/68) : Discover → Offer → Request → Ack (« DORA »), adresse prêtée pour un bail.
  • IMAP synchronise (mails sur le serveur), POP3 télécharge (mails sur l'appareil). SSH (22) chiffré remplace Telnet (23) en clair.

1. HTTP

Protocole entre le navigateur (client) et les serveurs web : une requête, puis une réponse.

Afficher http://www.cisco.com/index.html :

  1. Découper l'URL : http (protocole), www.cisco.com (serveur), index.html (fichier).
  2. Demander au DNS l'adresse IP du serveur, puis envoyer GET /index.html.
  3. Le serveur renvoie le code HTML.
  4. Le navigateur l'interprète et affiche la page.

URL : protocole://[user:password@]hôte[:port][/chemin][/document]. L'hôte est un FQDN ; le port par défaut de HTTP est 80.

2. DNS (Domain Name System)

Un paquet IP a besoin d'une adresse IP, pas d'un nom : le DNS traduit les noms de domaine en adresses, grâce à des serveurs de noms organisés en arbre.

FQDN www.exemple.com. (de droite à gauche)
. finalRacine (souvent omise)
comTLD : domaine de premier niveau (.com, .fr, .org)
exempleDomaine de deuxième niveau (celui qu'on enregistre)
wwwNom d'hôte : un service ou une machine

13 serveurs racines (a à m.root-servers.net), chacun répliqué sur des centaines de machines dans le monde : c'est le point de départ de toute recherche.

EnregistrementRôle
ANom → IPv4 (le plus courant)

PTRIP → nom (résolution inverse, in-addr.arpa)
NSServeurs de noms qui font autorité sur le domaine
CNAMEAlias vers un autre nom
MXServeur de messagerie du domaine
SOAInfos administratives de la zone (serial, refresh, retry, expire, TTL)
Résolution récursiveLe serveur interrogé relaie lui-même la requête de serveur en serveur (racine → TLD → serveur qui fait autorité) et renvoie la réponse finale.
Résolution itérativeLe serveur renvoie seulement l'adresse du prochain serveur à interroger. Utilisée si la récursivité est désactivée ou non demandée, et par les serveurs de premier niveau très sollicités.

3. DHCP (Dynamic Host Configuration Protocol)

Donne automatiquement leur configuration IP aux machines (client/serveur, extension de BOOTP). UDP, ports 67 (serveur) et 68 (client) : suffisant pour des échanges simples sur le LAN.

Le serveur a une plage d'adresses ; il donne une adresse libre, ou réutilise celle d'un client déconnecté. Adresse prêtée pour une durée limitée : le bail, renouvelable par un DHCPRequest.

MessageQuiRôle
1. DiscoverClient (diffusion)« Y a-t-il un serveur DHCP ? »
2. OfferServeurPropose une adresse IP
3. RequestClient (diffusion)Demande l'adresse proposée
4. AckServeurEnvoie la configuration complète
DeclineClientRefuse : la vérification ARP a obtenu une réponse (adresse déjà prise)
ReleaseClientRend son adresse en quittant le réseau
Moyen mnémotechniqueDORA : Discover, Offer, Request, Ack. Le client parle en premier et en dernier (Discover, Request), le serveur répond (Offer, Ack).

4. Messagerie : SMTP, POP3, IMAP

SMTP : envoi des e-mails. Port 25 entre serveurs de messagerie, port 587 pour les clients.

POP3 : connexion, téléchargement, lecture hors ligne. + simple, hors ligne ; − pas de synchronisation, perte possible des données.

IMAP : connexion, synchronisation, modifications en temps réel. + synchronisé, accès à distance, plusieurs appareils.

5. FTP, Telnet et SSH

FTP (sur TCP) : échange de fichiers avec deux canaux : contrôle (commandes, port 21) et données (transfert, port 20), pour séparer les rôles et envoyer des commandes pendant un transfert.

Limites : données et identifiants en clair. Alternatives sécurisées : FTPS (FTP sur SSL/TLS) et SFTP (via SSH).
